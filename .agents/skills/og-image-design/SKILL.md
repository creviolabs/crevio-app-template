# OG Image Design

Social sharing images are generated by a **server route** that renders to PNG with [`workers-og`](https://github.com/kvnang/workers-og) (Satori + resvg, the same engine behind `@vercel/og`). There are no file conventions and nothing is automatic: the card is a route, and the meta tags that point at it come from `seo()`.

## What this template ships

A site-wide card at [`src/routes/api/og.tsx`](../../../src/routes/api/og.tsx), served at **`/api/og`**. [`src/routes/__root.tsx`](../../../src/routes/__root.tsx) points every page at it:

```tsx
head: () => ({ meta: [...seo({ image: "/api/og" })] })
```

`seo()` ([`src/lib/seo.ts`](../../../src/lib/seo.ts)) emits `og:image`, `twitter:image` and `twitter:card: summary_large_image`, resolving the path to an absolute URL via `getAppUrl()`. Platforms reject relative image URLs, so always go through `seo()` rather than hand-writing the tags.

**It's a starting point, not a finished design.** Deliberately generic so a fresh site has a real card on day one — then you brand it.

## Building / rebranding the landing page

Treat the card as part of the landing-page pass — it's the first impression in every shared link, DM, Slack unfurl and search preview. When you build or restyle the homepage:

1. Open [`src/routes/api/og.tsx`](../../../src/routes/api/og.tsx) and match it to the site — see the `TEMPLATE:` notes inline.
2. Pull background and accent colors from the same palette as the page (the oklch theme in [`src/styles/app.css`](../../../src/styles/app.css)). **Convert to hex/rgb** — Satori understands neither `oklch()` nor CSS variables, which is why `COLORS` in that file is a hand-maintained copy.
3. Write a **headline that sells the click** — usually the hero's value proposition, not just the site name.
4. Swap the avatar for a real **logo** (inline `<svg>`, or an `<img>` Satori can fetch).
5. Preview at **`/api/og`** with `bun run dev`, then validate with the tools below.

## Overriding the card for one route

There is no file-convention override. A route sets its own image in `head()`:

```tsx
head: ({ loaderData }) => ({
  meta: seo({ title: post.title, image: post.coverUrl }),   // absolute or site-relative
})
```

`src/routes/_marketing/products/$slug.tsx` already does this, passing the product's first gallery image. For a *generated* per-route card, add another server route (e.g. `src/routes/api/og.blog.tsx`) reading a search param, and point `image` at it with the param filled in.

## Static images

Drop the file in [`public/`](../../../public) and reference it: `seo({ image: "/og-home.png" })`. Served as a plain asset, no render cost. Best for fixed marketing pages whose design is locked; generate when the card depends on data.

## Writing the generated card

```tsx
export const Route = createFileRoute("/api/og")({
  server: { handlers: { GET: async () => {
    const { ImageResponse } = await og();          // lazy — see below
    const account = await getAccountOrNull();      // reuse the cached loader
    return new ImageResponse(<div style={{ display: "flex", ... }}>…</div>, {
      width: 1200, height: 630,
      fonts: [{ name: "Inter", data: await font(), weight: 600, style: "normal" }],
    });
  } } },
})
```

> 🚨 **Import `workers-og` lazily.** It statically pulls in ~1.5MB of resvg/yoga wasm. A top-level `import` in a route file puts that in the route-tree chunk **every request loads** — measured at 547KB → 32KB when moved behind `await import("workers-og")`. Keep the `const og = () => import("workers-og")` indirection.

> **Satori gotchas:**
> - Only **flexbox** and a CSS subset — no `display: grid`, no float.
> - Every element with multiple children needs an explicit `display: flex`.
> - **No glyph outside the loaded font's coverage** (emoji, ★, →, non-Latin scripts). Satori fetches a fallback font at render time; on Cloudflare Workers that fetch 400s and the card 500s. Fix: use words/numbers (`4.9/5`, not `★ 4.9`) or inline `<svg>`, sanitize store-supplied text (see `ogSafe()` in the route), or load a font covering the glyphs.
> - Fonts are explicit: fetch a `.woff`/`.ttf` as an `ArrayBuffer` and pass it via `fonts`. The template uses `loadGoogleFont({ family: "Inter", weight: 600 })`, memoized per isolate — never fetch it per render.
> - Keep it self-contained: this runs in an isolated rendering context, not your React tree.

## Platform Specifications

| Platform | Dimensions | Aspect Ratio | File Size | Format |
|----------|-----------|--------------|-----------|--------|
| **Facebook** | 1200 × 630 px | 1.91:1 | < 8 MB | JPG, PNG |
| **Twitter/X (summary_large_image)** | 1200 × 628 px | 1.91:1 | < 5 MB | JPG, PNG, WEBP, GIF |
| **Twitter/X (summary)** | 800 × 418 px | 1.91:1 | < 5 MB | JPG, PNG |
| **LinkedIn** | 1200 × 627 px | 1.91:1 | < 5 MB | JPG, PNG |
| **Discord** | 1200 × 630 px | 1.91:1 | < 8 MB | JPG, PNG |
| **Slack** | 1200 × 630 px | 1.91:1 | — | JPG, PNG |
| **iMessage** | 1200 × 630 px | 1.91:1 | — | JPG, PNG |

**Universal safe bet: 1200 × 630 px, PNG, under 5 MB.** This is the default `size` for `ImageResponse` above.

## Design Rules

### Text

| Rule | Value |
|------|-------|
| Title font size | 48-64px |
| Subtitle font size | 20-28px |
| Max title length | 60 characters (truncated on some platforms) |
| Max subtitle length | 100 characters |
| Line height | 1.1-1.3 for titles |
| Font weight | Bold/Black for title, Regular for subtitle |
| Text contrast | WCAG AA minimum (4.5:1 ratio) |

### Safe Zones

- 40-80px minimum padding from all edges
- Some platforms crop edges or add rounded corners
- Never put critical text in the outer 5%

### Colors

| Background Type | When to Use |
|----------------|-------------|
| Solid brand color | Consistent series, corporate |
| Gradient | Modern, eye-catching |
| Photo with overlay | Blog posts, editorial |
| Dark background | Better contrast, stands out in feeds |

**Dark backgrounds outperform light** in social feeds — most feeds are white/light, so dark OG images pop.

## Consistency System

For a site with many generated images, factor the shared chrome into one helper and vary only the content:

| Element | Keep Consistent | Vary |
|---------|----------------|------|
| Background style | Same gradient / brand colors | — |
| Font family | Same font | — |
| Layout | Same positioning | — |
| Logo / branding | Same placement (corner) | — |
| Category badge | Same style | Color per category |
| Title text | Same size/weight | Content changes |

## Common Mistakes

| Mistake | Problem | Fix |
|---------|---------|-----|
| Static `import { ImageResponse } from "workers-og"` | ~1.5MB of wasm in the chunk every request loads | `await import("workers-og")` inside the handler |
| Hand-writing `og:image` meta tags | Relative URLs platforms can't fetch; duplicates | Pass `image` to `seo()`, which absolutizes via `getAppUrl()` |
| `display: grid` in `ImageResponse` | Satori silently misrenders | Flexbox only |
| Missing `display: flex` on a multi-child node | Satori throws at render time | Add `display: flex` explicitly |
| Emoji / ★ / arrows / non-Latin glyphs | Satori fetches a fallback font → **400s on Workers → card 500s** | Words or inline SVG; sanitize with `ogSafe()`; or load a covering font |
| Fetching the font per render | A network round-trip on every card | Memoize the `ArrayBuffer` at module scope, as the route does |
| Text too small | Unreadable on mobile previews | Title minimum 48px at 1200px width |
| Light background | Gets lost in white/light feeds | Use dark or saturated backgrounds |
| Heavy fetches in the handler | Slow generation, bot timeouts | Reuse the cached `@/lib/data` loaders; keep it lean |
| Reading `oklch()` / CSS vars in the card | Satori cannot parse either | Keep the hex `COLORS` copy in sync with `app.css` |
